# Data contract and local commands

This plugin is self-contained: Node 22.19+ and local engineering files are the only core dependencies. It has no OpenPnP dependency, machine connection, cloud service, credentials or installation-time package download.

## Canonical JSON

`schemaVersion: 1`; `board: {id, name, revision, widthMm, heightMm}`; `variant`; positive integer `quantity`; explicit `conventions: {units:"mm",coordinateFrame:"board-bottom-left",rotation:"ccw",bottomView:"top"}`; `bom` and `placements` arrays. Optional `authoritativePlacements` supplies an independent source snapshot for exact geometry comparison and bounded correction. Optional source metadata and findings preserve provenance and unresolved source questions. See the bundled JSON schemas.

Each BOM row has `ref`, `partId`, `value`, `package`, `category` (`smt`, `tht`, `mechanical`, `fiducial`), boolean `populated`, and `mpn` (string or null). Unknown identity stays unknown. SMT population requires placement rows. THT placements are optional; mechanical items and fiducials are not counted as populated SMT assembly operations.

Each placement has `ref`, `xMm`, `yMm`, `rotationDeg`, `side` (`top`/`bottom`) and optional `package`. Coordinates are in the declared board-bottom-left frame. Rotation is counterclockwise; bottom placements are expressed in the top view. A deliberate source transformation must be recorded in source provenance. Board bounds are rectangular envelope checks, not collision, clearance or DFM validation.

## CSV exchange

`import --project <dir> --brief <brief.json> --bom <bom.csv> --placements <placements.csv> --units mm --bottom-view top-view`

The brief contains the canonical board, variant, quantity and conventions, plus optional source metadata. Add `--authoritative <complete.csv>` when a complete reviewed source is available. `--mapping <columns.json>` accepts `{ "bom": {"ref":"Designators", ...}, "placements": {"ref":"Ref", "x":"PosX", "y":"PosY", "rotation":"Rot", "side":"Side"} }`. BOM semantic keys are `ref`, `partId`, `value`, `package`, `category`, `populated`, `dnp`, `mpn`. Placement semantic keys are `ref`, `x`, `y`, `rotation`, `side`, `package`. Unambiguous common headers are recognized; ambiguous columns require mapping.

BOM CSV must include explicit category and Populated or DNP. Grouped references separated by comma, semicolon or whitespace are expanded with source-row evidence. Units must be explicitly supplied or present in both coordinate headers. `--bottom-view negated-x` is only for a documented convention with bottom X negated and angle transformed as 180° minus source rotation. It does not infer an origin or reflect around an arbitrary board width.

## Optional native exports

`kicad-export --board <board.kicad_pcb> --output <new-directory> [--schematic <board.kicad_sch>] [--kicad <executable>]` uses argument arrays and bounded subprocesses to create native positions CSV, front/back SVG, optional schematic BOM and a hash/command receipt under `artifacts/`. The coordinate origin is KiCad's declared drill-file origin. Native rotation and bottom conventions still require review before canonical import. Source hashes cover the declared board and root schematic, not external hierarchical dependencies. DRC/ERC are not run by this adapter. Missing KiCad returns `KICAD_UNAVAILABLE`; use supplied exports to complete the core workflow. Failed runs retain diagnostics without replacing an existing export. Actual native-host qualification is separate from protocol tests.

## Checks, changes and output

The checker detects duplicate/missing/extra references, DNP placement, conflicting packages, declared bounds violations, and position/rotation/side mismatches against supplied authority. Geometry tolerances are recorded in the report. It does not authenticate upstream files or prove electrical equivalence. A valid authoritative source remains an engineering input, not a conclusion generated by the assistant.

Plans bind the base revision and exact candidate content by SHA-256. Applying a stale plan fails; replaying an already applied plan returns its prior revision. Every successful change creates a new immutable snapshot and fresh guide. `status`/`resume` reconstruct context from the project. A crashed process leaves a lock with PID and timestamp: inspect the process before removing that lock. Never remove an active lock.

Change previews distinguish assembly edits (`changes`) from CSV evidence line-number updates (`sourceRowChanges`). Inserting a CSV row can move later source lines without changing those components. Both are retained in the plan and revision history; the full candidate, including source-row metadata, remains hash-bound. A line-number-only rewrite is not an assembly change.

The handoff verifier parses exported CSV independently and compares its semantic rows with the immutable input. It recomputes checks and validates all listed artifact digests. SHA-256 detects changed content; it is not a signature or third-party certification. Keep supplied hardware license notices with derived fixture and handoff distributions.

Delivery publication reserves a new directory exclusively and writes its verified manifest last. A directory without `manifest.json` is incomplete; after an interrupted publication, preserve it for diagnosis and select a new delivery path. Existing handoffs remain untouched. Verify a handoff with the exact plugin version recorded in its manifest.
