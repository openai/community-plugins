# Owned initial Git delivery

The canonical operations caller supplies the original prepared image proposal, native commit, complete local transport, authenticated base observation, owned project authority and newly issued writer identity. The fixed writer makes one durable request claim and one Git receive-pack POST. Writer-token REST requests are GET-only. A separate original owner API session creates the merge request, checks its required jobs and merge gates, requests a source-pinned fast-forward merge once, and independently observes the watched revision. GitLab does not supply atomic target-head or pipeline-ID merge preconditions; the receipt records both limitations.

The writer token belongs to a fresh regular user with Developer membership on the exact owned deployment project and only read_api/write_repository scopes. The template pins its role, run, environment, target branch prefix and action expiry; future IDs and token bytes cannot be supplied in JSON. The original service administrator creates this identity during provision. Cleanup revokes its exact token, removes membership, then deletes the user. Unknown effects are retained and reconciliation reads only. Credentials and passwords never enter evidence. GitLab's date-only token expiry is broader than the local action window; current local expiry is always enforced, and cleanup must revoke the token.

An ObservedGitDelivery is a process-local original observation, not a serialized authority. Before merge it requires the live original image/transport inputs. After an observed merge it retains original origins and audits frozen proposal, native commit, transport and delivery artifact bytes; old upload expiry does not erase history or grant another write. Saved delivery JSON never reconstitutes this object. A failed continuation revokes the object and poisons the original owner write session. Transport renewal preserves the same credential, trust and uncertainty latch.

This candidate implements the initial build-promote delivery only. Policy fault, native correction and reset need their separate direct producers and explicit operation grants. Actual separately issued reader credentials, live GitLab/project provisioning, installed-package integration and the end-to-end recording are separate prerequisites. Tests use controlled upstream/native seams and disposable loopback TLS where stated; no live project, provider call or lab recovery was performed.
