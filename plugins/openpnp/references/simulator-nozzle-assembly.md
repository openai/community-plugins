# Create a complete simulator nozzle assembly

Use this workflow only when the current `configuration_changes` advertises `create_simulator_nozzle_assembly`. It creates a complete exact native `ReferenceNozzle`, independent Z and Rotation controller axes, Boolean vacuum valve, and compatible nozzle tip on the existing default head and its installed `NullDriver`. The new nozzle shares that head's existing direct X/Y axes. It appends the nozzle, preserving the default nozzle and camera frames.

This is software configuration for an isolated simulator. It does not install physical tooling, measure offsets, calibrate backlash/runout, verify vacuum, or qualify part placement accuracy. The dedicated controller-diagnostic profile does not expose this change.

## Plan and apply

1. Read capabilities, status and configuration. Resolve existing `head_id`, `driver_id`, `x_axis_id`, and `y_axis_id` from native readback. The simulator must be disabled and idle, every nozzle empty, and finite material setup unenrolled. Existing mapped/coupled routes and advanced/3D camera geometry are outside this creation profile. Do not remove those definitions to force admission.
2. Submit exactly one `create_simulator_nozzle_assembly` change in its own `openpnp_plan_configuration` call with the observed revision. Include unique nozzle/tip/valve names, explicit head offsets in millimeters, bounded Z home/limits/Safe Z/rates, separate Rotation home/limits/rates in **degrees**, dwell settings, tip geometry, and existing `exclusive_package_ids`. The tool schema is the field authority; arbitrary native class names, IDs, properties, actuator commands, or XML are not inputs.
3. Explain the compatibility effect: every selected package becomes compatible exclusively with the new tip. The new tip is compatible only with the new nozzle; other package definitions retain their current compatibility. Choose a mixed job with both selected and unselected packages when verifying the new and original tooling together.
4. Specify `simulated_initial_tool_state: installed-on-new-nozzle`. This initializes native simulator model state. It is not a manual installation acknowledgement. Automatic changing and part-on/off vacuum measurement remain disabled for the new assembly; the valve supports its native simulated pick/release sequence.
5. Apply the returned retained plan once. Planning creates no native objects or listeners. Apply first saves a portable pre-creation artifact and forces a `topology_recovery_available` journal event, then records the native effect and mutates the graph on the native executor. An unsupported or oversized portable preimage refuses creation before its first effect.
6. Poll the original operation. The successful result includes `created_assembly` with native-generated nozzle, tip, Z, Rotation and valve IDs, and `recovery_preimage` with artifact ID and SHA256. Duplicate requests return the original operation; do not change the request ID to repeat uncertain creation.
7. Read configuration and check all resulting identities, axis/valve/tip references, package compatibility and persisted fields. Creation invalidates homing, dependent calibration, board registration, job validation and existing plans. Enable/home and validate the job again before execution.

The bounded result admits at most four nozzles, 16 axes, 16 tips and 16 actuators. Rotational limits must cover at least −180° through +180°. Linear Safe Z is an explicit coordinate inside the Z limits, at or above home. The Z envelope must include bottom-camera Z plus selected part height after nozzle offsets, as well as feeder/board poses; high Z equal to zero can exclude bottom vision even though home and Safe Z fit. These are admitted native software settings, not measured collision clearance. The native motion planner remains responsible for its own commanded trajectory semantics.

## Verification

Use a real native mixed-package job and examine native placement-complete checkpoints plus successful pick/release action outcomes. Require both the original nozzle ID and the new nozzle ID, and the new tip ID on the new nozzle's records. A list entry, saved XML or successful setter alone does not demonstrate operation. Export/adopt the completed configuration into a fresh simulator and check reference persistence before a second native mixed job. Adoption preserves feeder counters; it does not refill simulated tapes. Reinspect feeder counts and preflight warnings. Counts alone do not establish remaining usable supply; a zero/unconfigured strip maximum means unknown capacity, not unlimited material. Choose a bounded verification job only when usable feed bounds are established; otherwise report repeat verification as incomplete. If feeding fails, preserve the original operation and reported state, including any `outcome_unknown`; do not reset counters, disable vision, or replay an unresolved action to force verification. Report actual counts separately from independent visual inspection or physical accuracy.

## Partial writes and recovery

Any failure after creation starts fences further configuration; an unfinished native effect is `outcome_unknown`. Keep the failed configuration, original operation/request ID, journal and recovery artifact. `topology_recovery_available` links the preimage to its operation even when the final response is missing. Read `openpnp_get_events` and `openpnp_get_native_artifact`; preserve the full raw journal if the bounded event page requires resynchronization.

Recover using [fresh portable adoption](portable-simulator-adoption.md) of the hash-verified preimage through the shipped `adopt-configuration` and `start-adopted-simulator` CLI commands. Use fresh adoption/state directories and a new session. A typed `openpnp_restore_configuration` snapshot cannot delete newly created objects and is not a rollback for topology creation. Do not manually remove partially created objects, replay an uncertain plan, patch live XML, or copy journals into the new generation. The new generation transfers no lease, homed/enabled state, job progress, board-load placement history, or material execution authority.
