# Camera and vision calibration

Bind every image/measurement to camera identity, resolution, capture time, working plane, lighting/settling mode, and calibration revision. A resized/cropped diagnostic image needs its transform before it can support metrology. Do not use an image-language estimate as a calibrated nozzle coordinate.

Inspect dependencies in the profile's order: camera scale/model, camera-to-nozzle offsets, runout/working heights, bottom vision, and board registration. Preserve valid manufacturer values. Physical focus or mounting corrections remain operator tasks when no qualified actuator performs them.

## Image-based settling

When the current runtime advertises `set_camera_dynamic_settling` and the selected camera reports `dynamic_settling_editable: true`, stage the complete change through `openpnp_plan_configuration`: `camera_id`, `method` (`Maximum`, `Mean`, `Euclidean`, or `Square`), `timeout_ms` (20–5000), `debounce` (0–10), `threshold_percent` (>0 and ≤100), and `full_color`. Preview and apply against the current configuration revision. The supported simulator profile uses exact native `ImageCamera` and `SimulatedUpCamera` classes with bounded frame sizes and supported preprocessing. An unavailable profile or field is a capability gap; do not fall back to arbitrary Java properties. Fixed-time settling remains the separate `set_camera_settling` change.

Use `openpnp_capture_camera` with `mode: "settled"` to exercise the native method after enabling the simulator. A returned artifact proves that capture returned a frame. OpenPnP's native API does not distinguish successful image settling from expiration of the settling loop's timeout. Its timeout is also not a hard deadline for camera I/O. Read the artifact's `metadata`: `capture_status`, `settling_outcome`, `image_validity`, `physical_calibration_validity`, and the admitted settings. Do not report a returned frame as stable, valid, or physically calibrated from this receipt alone. Raw capture does not request settling. Native recorded settling time is diagnostic timing, not a detector-quality result.

Compare retained captures using an independently defined image-quality or measurement criterion before claiming improvement. Identical frames can run until the native timeout; a shorter elapsed time alone does not establish a better setting. A camera change invalidates affected prior measurements even when a later frame looks plausible.

Portable configuration admission currently requires fixed-time settling. If a dynamic source is refused, preserve its settings and the refusal. A supported typed backup/restore and a portable adoption are different operations; do not silently convert the source to make an export pass.

For a supported active dynamic method, typed backup/restore retains its active fields and the latent fixed dwell. A FixedTime snapshot restores the fixed dwell and explicitly omits inactive dynamic parameters; inspect `snapshot_omissions` before describing the restore scope.

## Vision and calibration

For pipeline tuning, inspect the effective machine/package/part setting and its inheritance. Prefer the smallest intended specialization; a shared setting can affect unrelated parts. Stage only typed parameters supported by the adapter. Compare positive and negative examples before accepting a change, and do not weaken detection thresholds merely to silence an error.

OpenPnP bottom vision measures pickup translation/rotation with an upward camera and supplies a correction to job processing. Its settings inherit from machine to package to part. [Bottom Vision](https://github.com/openpnp/openpnp/wiki/Bottom-Vision)

Nozzle-tip calibration measures runout and tool-specific camera relationships. Correct nozzle offsets are prerequisites, and changed offsets invalidate tip calibration. Use the selected native routine instead of inventing compensation values. [Nozzle-tip calibration](https://github.com/openpnp/openpnp/wiki/Nozzle-Tip-Calibration-Setup)

`openpnp_run_calibration` supports `recipe_id: "nozzle-tip-runout"` with `nozzle_id` and optional `enable`. It performs the native routine in the simulator. `openpnp_validate_calibration` reads that nozzle's existing native calibration model; it does not collect new validation measurements. Returned `fitted_offsets` sample the fitted correction model at eight angles. They are not measured residuals or independent accuracy checks. Camera scale uses the separate recipe below when its runtime prerequisite is available. Keep missing residual/threshold evidence explicit.

Return images, accepted/rejected observations, residuals, thresholds, and affected dependencies. A plausible-looking preview alone does not validate calibration.

## Planar camera scale measurement

Check `camera_planar_scale.runtime.available` first. This requires the packaged native circular-symmetry fix and its complete verified class family. The recipe measures an exact head-mounted down-looking `ImageCamera` using direct NullDriver X/Y axes and fixed virtual Z/rotation. It does not implement lens calibration, camera-to-nozzle offset calibration, axis scale calibration, or physical metrology.

1. Read the selected camera, working plane, current geometry and native motion bounds. Enable and home the simulator under its control session. All native nozzles must be empty and within their safe-Z zones. Unsupported mapped/backlash axes, advanced/3D/lens models, transforms, preprocessing or native classes are admission gaps; do not change unrelated settings merely to silence a refusal.
2. Capture the existing camera once before changing approximate scale. This initializes the simulator's image source and independent renderer scale; the measurement does not initialize or replace those private values. Retain the raw artifact. Use typed `set_camera_settling` to configure FixedTime 600–1000 ms when that change belongs to the requested calibration. The measurement calls native settled capture without optional light actuation and preserves existing light values.
3. Select one isolated circular feature at the declared working plane from known fixture coordinates or other valid coordinate evidence. Use `openpnp_plan_motion` with `tool_id` set to that camera’s `camera_id`, then `openpnp_execute_motion`, to position the camera. Never convert an uncalibrated image-language estimate directly into a machine move. Confirm a 640×480 native frame, approximate positive X/Y scale, and target diameter within 12–96 pixels. The native recipe uses a fixed central search region; it does not prove that the entire source image contains only one feature.
4. Submit `openpnp_run_calibration` with `recipe_id: "camera-planar-scale"`, the actual `camera_id`, `displacement_mm` within 0.5–2, integer `expected_feature_diameter_px` within 12–96, current `session_id`, a fresh canonical UUID `request_id`, and mandatory current `expected_config_revision`. Do not include nozzle fields, `enable`, custom scripts, tolerances, thresholds, or apply options.
5. Follow the original operation. A successful measurement makes seven fixed native moves and retains eight captures: baseline, four training observations, two holdout observations and final baseline. Training pairs need at least 12 pixels of displacement; the fixed policy requires score ≥1.5, supported image-motion signs, ≤1% cross-axis response, ≤20% change from approximate scale, and ≤1 pixel holdout/final-baseline error. These are simulator image prediction checks. A returned frame does not independently establish optical stability or physical positioning accuracy.
6. Inspect `measurement_status`. A rejected measurement returns its reason, captured observations and last native pose without a cleanup move. On acceptance, inspect `configuration_proposal_status`: only `available` supplies `proposed_configuration_change`. Typed geometry limits can make a valid measurement's proposal unavailable. Preserve that measurement and report the exact proposal error.
7. Retrieve every observation's `artifact_id` with `openpnp_get_native_artifact`; preserve its SHA-256, pose, detection, source-pixel identity and configuration revision. When the available proposal matches the requested work, preview it using `openpnp_plan_configuration`, then apply with `openpnp_apply_configuration` and the current revision. Measurement alone never saves or changes geometry. Applying camera geometry invalidates cached native fiducial transforms, registration, nozzle runout and job validation; refresh affected work before a job starts.

Loss of authority, revision changes or native/model/persistence failures stop the sequence. If an effect is unresolved, preserve its original operation and evidence; do not generate another request to repeat it. No return-to-origin motion runs as failure cleanup. Known quality rejection can leave the camera away from baseline, so read the last native pose before planning any later authorized move.

The untouched pinned stock simulator has a verified example at its first sample fiducial, approximately X 5.994319 / Y 6.413460 mm, Z 0, using a 24-pixel feature and 1 mm displacement. Use this example only after confirming that exact default fixture and its original image/geometry are selected; these are not generic machine coordinates. In the recorded trial, holdout errors were 0.224 and 0.602 pixels, while the inferred Y scale differed from the independent renderer by 2.71%. Passing the one-pixel check therefore does not establish 2% absolute scale accuracy. Do not describe this receipt as physical qualification or independent placement inspection.
